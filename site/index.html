[ 01 ] — The gap

The agent reads the tool, then trusts it.

To know what a tool does, the agent reads the tool's own description — and believes whatever it returns. An attacker who controls that text can slip in an instruction the agent will carry out.

A weather tool asks for the weather.
A poisoned one asks for a wire transfer — in the same breath.

[ 03 ] — Architecture

A checkpoint on every request.

MCPShield is a transparent proxy. The agent thinks it's talking to its tools; the tools think they're talking to the agent. Nothing passes without inspection.

[ 04 ] — Threat playbook

Six ways a tool cheats. Each one caught.

The attacks MCPShield is tested against, in plain terms — and how each is intercepted.

01

Tool poisoning

The tool's own description hides an order the user never gave.

Intercepted by

Reading every description and decoding anything hidden inside it.

02

Shadowing

One tool's text rewrites how a different, trusted tool behaves.

Intercepted by

Flagging any tool that references tools it doesn't own.

03

Rug pull

Safe when approved, then it quietly swaps in a harmful description.

Intercepted by

Fingerprinting each tool and quarantining any later change.

04

Hidden in a reply

An order smuggled inside returned data — an invoice note, a web page.

Intercepted by

Treating every reply as untrusted and scrubbing it clean.

05

Split payload

One instruction broken across several tools so none looks guilty alone.

Intercepted by

Checking all the descriptions together, not one at a time.

06

Data exfiltration

An innocent field begging to be filled "for the logs" — with secrets.

Intercepted by

Spotting leaky fields and scanning for secrets before anything leaves.

[ 06 ] — Under the hood

Six agents, one verdict.

For the technical reviewer. Each request is judged by a small team of specialist agents.
